`npm audit --omit=dev` now reports:

- `postcss`: moderate XSS advisory via Next transitive dependency.
- `uuid` / `gaxios`: moderate buffer bounds issue.

Resolved in this pass:

- `next` lockfile resolution moved from `16.1.6` to `16.2.9`.
- `ws` lockfile resolution moved from `8.19.0` to `8.21.0`.
- The high-severity production findings are no longer present in `npm run audit:prod`.

Recommendation:

- Do not run `npm audit fix --force`; npm currently suggests breaking or invalid downgrades for this tree.
- Re-check once patched `next` and `google-auth-library` / `gaxios` versions are available within safe semver ranges.
- Keep production dependency risk visible until `npm run audit:prod` is clean.

## Refactor Advice

### 1. Extract drill engines from pages

Before this pass, `apps/web/src/app/acronyms/page.tsx` and `apps/web/src/app/phonetic/page.tsx` duplicated the same quiz ideas:

- random current item
- 3 choices
- stable shuffled options per question
- streak counter
- correct auto-advance
- wrong-answer correction panel
- timeout cleanup

Status:

- Extracted `useThreeChoiceDrill`.
- Kept content-specific question builders separate:
  - `buildAcronymQuestion`
  - `buildPhoneticQuestion`

This should reduce future behavior drift between acronym and phonetic drills.

### 2. Move static drill data out of route components

Before this pass, the acronym and phonetic data arrays lived inside page components.

Status:

- Moved them to `apps/web/src/lib/drills/acronyms.ts` and `apps/web/src/lib/drills/phonetic.ts`.
- Exported builders and typed entries from those modules.
- Page components now focus on layout and state wiring.

### 3. Split v2 shell from v1 route modules

Some v2 pages are wrappers around v1 route pages. This was useful for fast rollout, but it limits route migration and creates visible loading states.

Recommendation:

- Extract reusable feature components from v1 route files.
- Have both v1 and v2 pages import those components.
- After that, legacy routes can redirect cleanly without circular route dependencies.

### 4. Add first-party E2E tests

Current confidence comes from Vitest plus production screenshot smoke checks. That is good for regression coverage but not a true user-flow gate.

Recommendation:

- Add `@playwright/test` to the repo.
- Create smoke tests for:
  - `/` redirects or lands on v2
  - `/v2` dashboard has 350 questions
  - `/v2/acronyms` quick quiz has 3 options and auto-advances on correct
  - `/v2/phonetic` quick quiz has 3 same-letter options and shows correction on wrong
  - `/v2/exam` starts an exam and renders a question
  - `/v2/charts` opens a figure/reference view

### 5. Separate hard and advisory content checks

The current `validate` script fails on figure-context audit even when the runtime bank is valid. That makes CI status hard to interpret.

Recommendation:

- `validate:required`: schema, runtime bank build/check, no invalid question contracts.
- `validate:advisory`: figure context, citation quality, overlap, collection health.
- `ci:verify`: run required checks as gates and advisory checks as report-only until the debt is burned down.
